# Gameble Score 小程序

这是 [gameble-score](https://github.com/yorkchung0409/gameble-score) 的原生微信小程序客户端，可直接在微信开发者工具中导入本仓库根目录。

项目通过微信云函数访问 MySQL 账本，不需要运行云托管，也不需要在小程序后台配置服务器域名。

1. 在 `project.config.json` 填入你的小程序 AppID。
2. `app.js` 中的 `CLOUDBASE_FUNCTION_ENV` 必须与已部署 `gameble-bootstrap-probe` 的云开发环境一致。
3. 在微信开发者工具上传 `cloudfunctions/gameble-bootstrap-probe`，并在函数环境变量中配置独立 MySQL 账号的 `DB_HOST`、`DB_PORT`、`DB_USER`、`DB_PASSWORD`、`DB_NAME`；若要保留“我的”页管理员入口，也设置 `ADMIN_WECHAT_OPENIDS`。函数目录内的 `config.json` 会为同一函数注册每日历史清理触发器。

首次部署新版本前，在后端目录执行一次 `node scripts/migrate-db.js`。本次迁移增加 `users.nickname_changed_at`，并将已有自定义昵称标记为不可再次修改；迁移脚本可重复执行。

上传云函数后，在云开发控制台的“触发器”列表确认 `dailyRetentionCleanup` 已启用；它会每天清理六个月以前的明细并累加历史快照。无需启动或更新云托管服务。

`wx.cloud.callFunction` 会把微信身份交给函数运行时，服务端使用注入的 OpenID 建立用户，不需要将 AppSecret 配置到任何运行环境。昵称使用 `input type="nickname"`，由用户主动选择或输入；不会使用已失效的直接用户资料授权接口。

当前项目不含图片对象存储，故未在小程序中持久化微信头像临时文件。接入头像时，应增加对象存储上传接口和 CDN URL 字段，不能把临时路径直接写入数据库。

## 功能

- 扑克工具：首页进入个人记账或本机保险计算。个人记账通过微信身份保存在云端，同一小程序、同一微信账号跨设备同步；原多人扑克账本保持下线。
- 麻将：微信身份登录、昵称设置、创建或加入房间、转账记账与冲正。
- 实时性：麻将房不建立实时推送长连接；前台每 15 秒通过云函数检查一次轻量房间版本，只有版本变化时才读取完整账本。自己的操作由写接口立即返回结果。

## 保险 outs 选择（2026-10-08）

完成牌面计算后，点每街「当前 outs / 已选 outs」的张数，按花、顺、高张、三条 / set、两对、葫芦等类型或单张牌选择；点「确认应用」后按去重后的张数统一计价。关闭弹窗会放弃修改。高张指对手高于原公共牌最高点数的手牌击中一对后反超；同一张牌可属于多个类型，但只算一次、赔一次。超过 17 张保留实际张数，价格沿用 17 outs 档。

默认购买全部 outs，相同牌面再次计算保留选择；手动拖动滑条回到手动档位，点击本街「自动」恢复全部真实 outs。发牌后冻结上一街的选择与金额，只能查看；发出转牌后河牌按四张公共牌重新计算，不继承翻牌时的预估选择。本机草稿保留选择，旧草稿按全部触发牌已投保恢复。

未购买的危险牌命中时，无保险赔付，净损失为实际投入加上已经支付的保险费。转牌终局只扣转牌已付保险费，不扣河牌预填金额；河牌终局扣两街已付保险费。未投保反超风险也计入预期收益与最差收益。本次仅更新小程序本机保险模块，无需 SQL 或云函数更新。

多人底池支持在「底池与投入」填写 0–100% 的抽水比例，允许小数百分比。每个主池、边池按原金额 ×（1 − 比例）计算净额后按十位四舍五入，保险金额上限、实收与盈亏使用扣水后的金额；各池金额旁显示抽水比例和该池实际扣除金额，例如「抽水 5% · 扣 40」。由于底池按十位取整，实际扣水可能比精确百分比多或少。退回的未跟注金额不参与抽水，玩家实际投入保持原值。比例为 0 时保持原有底池金额；单一底池仍直接输入可保底池。抽水比例保存在本机，发牌后锁定，重置或重新开始牌局后可修改。旧草稿默认不抽水。

## 账本模块下线

本次需要重新上传小程序和 `gameble-bootstrap-probe` 云函数。首页、我的、历史及运营页不再展示或统计扑克账本；首页和个人数据查询不再读取旧账本。云函数拒绝旧账本操作，历史归档工具仍保留以维护已有数据。后端 Web 应用不在本次删除范围。

## 个人记账接入（2026-09-28）

部署顺序：

1. 在 `gameble_score` 的 SQL 编辑器执行后端 `scripts/20260928-personal-bookkeeping.sql`，或在后端终端执行 `node scripts/migrate-db.js`。前者是 SQL，后者是终端命令，不要混用。迁移只新增 `personal_bookkeeping` 表及版本记录，不清空原有数据。
2. 上传并部署完整 `cloudfunctions/gameble-bootstrap-probe`（云端安装依赖），包含 `bookkeeping-core.js`、`bookkeeping-model.js` 和更新后的入口、个人汇总代码。沿用现有数据库环境变量；运行账号需要新表的查询、插入、更新、删除权限。
3. 编译、上传小程序。首页「个人记账」可新增、编辑、删除记录；「我的」总输赢为个人扑克盈亏与麻将净输赢之和。

每笔包含日期、可选时长（小时，支持小数，例如 3.5）、输/赢积分、盲注、多标签和备注。旧版分钟记录读取时自动除以 60，已有小时记录直接使用原值；编辑其他字段不会将旧时长取整。支持筛选、统计、排行、趋势、JSON 备份合并与 UTF-8 CSV 追加导入。为兼容旧文件，CSV 必需列仍为「日期、时长（分钟）、盈亏」，导入后自动换算为小时显示；日期使用 `YYYY-MM-DD`，输用负数；可选「标签、备注」。Excel 文件需先另存为 CSV，不能直接导入 XLSX。

记录只由云函数从平台 OpenID 定位本人，不接受客户端指定他人的用户 ID；没有离线自动保存。进入页面或下拉刷新拉取云端记录，每次保存检查版本，其他设备已修改时提示刷新，避免静默覆盖。数据管理里的清空只影响本人的个人记账。

当前每人最多 2000 条，记录内容上限 800 KB，导入文件不超过 1 MB；超限拒绝保存，不会截断数据。JSON 导入先预览再合并：同 ID 同内容跳过，同 ID 不同内容列出冲突并保留现有记录，不清空账本。CSV 追加导入没有稳定 ID，不会自动去重。个人记账不纳入六个月明细清理。

2026-10-08 加载优化：本次打开小程序后，已确认的个人记账保留在按用户隔离的内存缓存中。再次进入或返回页面时先检查云端版本；版本相同时不下载记录分段，返回仍已打开的页面也不重置其筛选、明细展开数量和走势选择。其他设备更新后，首个响应直接带回新版本的第一段，后续继续按同一版本读取；下拉刷新强制重新读取全部分段。成功新增、编辑、删除、导入和清空会更新缓存，失败的写入不更新。缓存不写入本机持久存储，重开小程序仍需首次完整读取。需要重新上传完整 `gameble-bootstrap-probe` 云函数并编译小程序，无需 SQL 迁移；旧云函数仍可使用完整读取路径。

### 网页 JSON 兼容更新

2026-09-29 单笔保存优化：新增、编辑、删除使用协议 3 的 mutate 操作，只发送本条记录和盲注/标签字典差异，正常一次云函数调用完成；返回仅含确认版本，本地据已确认内容更新视图。事务检查原版本并以操作编号和内容识别重复请求。大批量导入、清空仍走分段替换；超大的选项差异也回退分段。云端仍使用原有 JSON 表存储，因此不需要 SQL 迁移。先上传完整云函数，再重新编译小程序；不能承诺固定真机耗时。

支持网页原始 `{ records, blinds, tags }`、旧小程序 version 1 备份和 version 2 备份。云端保存规范字段 `result/amount/duration/blind/tags/note`，其中 duration 单位为小时、允许 null；分钟仅作为内部兼容字段，表单与记录列表均使用小时，无需批量重写数据库。未使用的盲注、标签字典也随备份保留。导出为 `{ format: 'york-bookkeeping', version: 2, records, blinds, tags }`，不承诺未经验证的网页端回导。

本次不需要再次执行 SQL。必须先上传新版完整云函数，再编译小程序。传输协议 `formatVersion: 3` 将备份按 12000 字符分段上传与读取，避免单次调用数据超限；磁盘备份仍为 version 2。上传分段暂存在本人数据库行的内部字段，读接口不返回暂存内容；完整收齐并校验后才原子替换正式记录、增加版本号。中断不改变正式记录，新上传覆盖旧暂存；暂存超过一小时不能继续提交。读取期间版本变化会重新读取一次，不拼接不同版本。提交响应丢失可安全重试，不重复导入。已有云端旧数组仍兼容，无需清空或重建表。

真机验收：同一微信在设备 A 新增记录，设备 B 进入页面或下拉刷新可见；两边同时打开编辑框，A 保存后 B 保存应提示刷新，不能覆盖 A；不同微信不能看到彼此记录。开发测试使用模拟身份与数据库，不能代替此真机验证。

## 上传与回归

- 微信开发者工具应直接导入本仓库根目录；部署后端压缩包不会改变开发者工具的小程序目录。
- 本地路径约定：小程序固定使用 `gameble-score-miniprogram/` 根目录；工作区 `outputs/` 中带年月日和序列号的压缩包用于函数和后端留档，不要导入小程序项目。
- 上传体验版前可执行 `node --test tests/*.test.cjs`，覆盖冷启动预热、并发登录、四人麻将转账、防重复写入、房间版本增量刷新、麻将历史分页与保险计算。
